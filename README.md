# WORD UP — 英単語テスト

**スマホで使う：[英単語テストを開く](https://sora39000.github.io/english-word-test/)**

iPhoneのSafariで上のリンクを開けば使えます。PCやPowerShellを起動しておく必要はありません。共有メニューの「ホーム画面に追加」で、次回からアイコンを押して開けます。

大学の英単語学習用の、記述式Webアプリです。HTML・CSS・JavaScriptだけで動き、無料のGitHub Pagesに置けます。データベース、APIキー、ログイン、npmパッケージのインストールは不要です。PCでCSVを更新し、公開URLをiPhoneのSafariから開いて使います。

### 添付CSVの確認結果

- 全50問。必須項目の空欄・同一問題文と正答の重複はありません。
- 列：`FrontText,BackText,Comment,FrontTextLanguage,BackTextLanguage`
- `FrontText` に英文と日本語がセル内改行で入っています。画面でも改行を保ちます。
- `BackText` が正答です。例：最初の問題の正答は `suitable`。
- `index` 列はありません。現在はデータの行順を1〜50として使用します。
- `Comment` と言語指定列は保持しますが、出題には使用しません。
- 元の `文.csv` は変更していません。アプリのデータは `words.csv` にコピー済みです。

## 2. PCで起動する

1. 初回だけ [Node.js公式サイト](https://nodejs.org/) からLTS版をインストールします。すでにNode.jsが入っていれば不要です。
2. エクスプローラーで `word-practice` フォルダーを開きます。
3. アドレスバーに `powershell` と入力してEnterを押します。フォルダー内を作業場所にしたPowerShellが開きます。
4. 次のコマンドを入力します。

   ```powershell
   node serve.mjs
   ```

5. 「Local: http://127.0.0.1:4173/」と表示されたら、PCのブラウザで **http://127.0.0.1:4173/** を開きます。
6. 終わったらPowerShellで **Ctrl+C** を押すとサーバーが停止します。

`npm start` でも起動できます。Windowsでnpmの実行ポリシーエラーが出る場合は、上記の `node serve.mjs` を使ってください。`npm install` は不要です。

**index.htmlをダブルクリックして開く方法ではCSVを読み込めません。** 必ず上記URLから確認します。`EADDRINUSE` が出たら、すでに起動している同じサーバーを使うか、そのサーバーのウィンドウでCtrl+Cを押してからやり直してください。

このローカルURLはPC専用です。iPhoneからPCの `127.0.0.1` を開いても使えません。スマホでは下記の公開URLを使います。

## 3. アプリの使い方

1. スタート画面で出題範囲と問題数を選びます。
2. 「通常テストをはじめる」か「苦手問題を練習する」を押します。
3. 問題文を読んで、`BackText` に対応する英単語を入力します。
4. 「採点する」またはEnterで答え合わせ。正解は緑、不正解は赤と記号・文字で表示します。正答も表示します。
5. 「次へ」またはもう一度Enterで進みます。未採点のまま次へは進めません。
6. 最後に「結果を見る」を押すと、得点・正答率・間違えた問題・入力した答えが表示されます。
7. 「間違えた問題だけ再テスト」「もう一度」「新しいテスト」から続けられます。

入力の大文字・小文字と前後の空白は無視します。単語の途中の空白やスペル違いは不正解です。空欄で採点した場合も不正解です。複数の正答をスラッシュで区切る機能はありません。CSVの `BackText` の文字列と照合します。

元CSVの `found` や `duty` などは、そのまま正答として扱います。問題文に `ed`、`s`、`ies` が書かれていても、入力するのはCSVにある正答です。

### 出題範囲と問題数

| 設定 | 動作 |
|---|---|
| 全範囲を混ぜる | CSV内のすべての問題を混ぜて出題。総復習したいときだけ選ぶ |
| 最新の範囲 | 最新の50番号単位の範囲のみ。100問なら51〜100、75問なら51〜75が対象。以前の範囲から補充しない |
| 1〜50、51〜100、101〜150… | 50番号ごとの範囲。CSVを増やすと自動で選択肢が増える |
| 全範囲の間違えた問題のみ | 全範囲で直近の回答が不正解のもの。正解し直すと対象から外れる |
| 10・20・30・50・全問題 | 選択した範囲から指定数を出題。対象が少なければその問題数に調整 |
| 苦手問題テスト | 選択範囲のうち、回答済みで累計正答率80%未満の問題のみ |

通常テストは重複なしでランダムに選び、順番もランダムです。苦手テストは正答率が低い順に選び、同率はランダム、選んだ後の出題順もランダムです。未学習の問題は苦手には含めません。

**次の50問だけ練習するには、出題範囲を「51〜100」にします。** そのうえで問題数を「全問題」にすると、その50問だけを練習できます。「10問」なら51〜100から10問を出します。通常テスト・苦手テスト・結果画面からの再テストも、その範囲内で完結します。最初の50問は混ざりません。起動時は前回選んだテストを復元します。未保存の場合は英単語テスト①から始まります。

「もう一度」は通常テストなら同じ範囲・問題数から再抽選します。2問以上では直前とまったく同じ並びを避けます。1問だけの場合は順番を変えられません。苦手テストと間違いだけの再テストの「もう一度」は、その回の問題を並べ替えて復習します。最新の苦手状況で再抽選したいときは「新しいテスト」に戻ってください。

### 学習記録

- 各問題の正解回数、不正解回数、直近の正誤、累計正答率を採点のたびにlocalStorageへ保存します。
- 同じテストの採点ボタンを連打しても二重に記録しません。
- 累計正答率は「正解回数 ÷（正解回数＋不正解回数）」です。表示は整数%に丸めます。
- 「学習状況」に問題数・学習済み問題数・正解数・不正解数・正答率・完了テスト数・苦手単語・全単語の記録を表示します。
- 最高点は、完了したテストの**実際の問題数ごと**に保存します。例えば9問の復習は「9問テスト」の記録になります。範囲・モードは区別しません。
- 中断したテストは最高点・完了回数に含めません。採点済み問題の記録は残ります。テスト途中の問題位置は保存しません。
- 同じ問題文と正答が同じ問題を識別するキーになります。末尾への追加・並べ替え・index列の追加では既存記録は引き継がれます。問題文や正答を変更すると別の問題として扱われます。
- CSVから除いた問題の記録は保管されますが、現在の単語の集計には含めません。最高点と完了回数は過去の全テストの記録として残ります。

記録は端末・ブラウザ・サイトURLごとに独立します。PCとiPhone、Safariと別ブラウザ、ローカルURLとGitHub Pagesでは共有しません。同じ公開URLを普段使うブラウザで開いてください。プライベートブラウズやブラウザデータの削除では記録が消えることがあります。保存できない場合はアプリ内に通知します。

同じブラウザで複数のタブを開いて同時にテストする用途は想定していません。ひとつのタブで学習してください。

## 4. GitHubへアップロードする

1. [GitHub](https://github.com/) にサインインします。アカウントがなければ作成します。
2. 右上の「+」から **New repository** を選びます。
3. Repository nameを、例えば `english-word-test` にします。
4. 無料公開用に **Public** を選びます。「Add a README file」を有効にして **Create repository** を押します。
5. 作成したリポジトリの **Add file → Upload files** を開きます。
6. PCの `word-practice` フォルダーの**中身**をドラッグ＆ドロップします。フォルダーそのものやZIPだけをアップロードしないでください。リポジトリを開いてすぐ `index.html` と `words.csv` が見える配置にします。
7. Commit changesに `Add word practice app` などの説明を入れ、**Commit changes** を押します。READMEは同梱版に置き換えます。

`tests` フォルダー、`serve.mjs`、`package.json`、説明書も一緒に置いて構いません。公開にビルド処理は不要です。`.nojekyll` がアップロードできなければ **Add file → Create new file** で `.nojekyll` という名前のファイルを作成します（中身は空、空を保存できなければ改行1つ）。

公開リポジトリではCSVの問題と正答も公開されます。

## 5. GitHub Pagesで公開する

1. リポジトリ上部の **Settings** を開きます。
2. 左側の **Pages** を選びます。
3. **Build and deployment → Source** を **Deploy from a branch** にします。
4. **Branch** を `main`、フォルダーを **/(root)** にして **Save** を押します。
5. 公開処理が終わるまで少し待ちます。**Actions** タブで処理状況を確認できます。
6. Settings → Pagesに公開URLが表示されます。通常は `https://あなたのユーザー名.github.io/english-word-test/` の形です。
7. そのURLをiPhoneのSafariで開きます。

このアプリはGitHub Pagesへ公開済みです。実際の公開URLは https://sora39000.github.io/english-word-test/ です。上の手順は、別のリポジトリへ配置する場合の説明です。

公式手順：[GitHub Pagesの公開元を設定する](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

### iPhoneのホーム画面へ追加

Safariで公開URLを開き、共有メニューから「ホーム画面に追加」を選びます。ホーム画面用のアイコン・アプリ名・縦画面向けレイアウトを設定済みです。iOSの版によって共有メニューの位置は異なります。保存領域の扱いが変わる場合があるため、追加後はホーム画面から継続して使い、初回に記録が維持されることを確認してください。

問題データは起動時に取得するため、ページを新たに開くときはインターネット接続が必要です。オフライン起動用のService Workerは使用していません。読み込み済みのテストは通信なしでも進められます。

## 6. 次回50問を追加する具体的な手順

### 最も簡単な方法：indexなしで末尾に追加

1. PCの `word-practice/words.csv` を別の場所にコピーしてバックアップします。
2. `words.csv` をExcelなどで開きます。文字化けする場合はExcelの **データ → テキストまたはCSVから** でUTF-8を指定して読み込みます。
3. 既存の50問の下に、新しい50問のデータを貼り付けます。Excel上では1行目が見出し、2〜51行目が既存50問、新規50問は52〜101行目です。
4. A列 `FrontText` に問題文、B列 `BackText` に正答を入れます。現在のC〜E列も残してください。新規行のCommentは空欄、言語列は元データと同じ `en-US` で構いません。
5. 追加元のCSVにもヘッダーがある場合、**見出し行は貼り付けません**。問題データだけを追加します。
6. **名前を付けて保存 → CSV UTF-8（コンマ区切り）** を選び、ファイル名を `words.csv` にして保存します。Excelの「CSVでは一部の機能が失われる」確認ではCSV形式を使用します。`.xlsx` やタブ区切りでは保存しないでください。
7. PCでアプリを起動・再読み込みし、「収録問題100問」「51〜100」が表示され、前回選んだ範囲が維持されることを確認します。
8. GitHubのリポジトリで **Add file → Upload files** を開き、更新した `words.csv` を同じ場所へアップロードして **Commit changes** を押します。同じ名前の既存ファイルが置き換わります。
9. **Actions** でPagesの更新完了を確認し、iPhoneで公開ページを開き直すか再読み込みします。収録問題が100問になれば更新完了です。

次はさらに末尾へ50問追加して150問、その次は200問にするだけです。JavaScriptやHTMLの修正は不要です。

**新しい50問だけでwords.csvを置き換えると、既存の50問は出題されなくなります。** 累積100問・150問のCSVを保存してください。テキストエディター上の物理的な行数は問題数ではありません。元CSVはセル内改行があるため、1問が複数行に見えます。Excel等でセル単位に編集するのが確実です。

### indexで番号を固定する方法（任意）

問題を並べ替える予定がある場合は、Excelで新しい列を追加して見出しを `index` にします。列の位置はどこでも構いません。

- 既存50問には `1`〜`50` を割り当てます。
- 次の50問には `51`〜`100`、その次は `101`〜`150` を割り当てます。
- すべての行に重複しない1以上の整数を入れます。空欄・0・小数・重複番号はエラーになります。
- 以後は一度割り当てた番号を変えずに使います。
- `index` がある場合、「最新の範囲」は最大のindexを含む50番号単位の範囲です。例えば最大75なら51〜100にある問題だけが対象です。indexがない場合はCSVの行順を番号にします。
- 後からindex列を足しても、問題文と正答が同じなら記録を引き継ぎます。

## 7. 困ったとき

| 症状 | 確認すること |
|---|---|
| CSVが読み込めない | `node serve.mjs` で起動しているか、`index.html` と同じ階層に `words.csv` があるか |
| 文字化け・UTF-8エラー | Excelの「CSV UTF-8（コンマ区切り）」で保存し直す |
| 列数や引用符のエラー | セル内のカンマ・改行は引用符で囲む必要がある。Excelで編集・保存すれば自動処理される |
| 新しい50問が表示されない | 既存問題に追記したか、ファイル名は `words.csv` か、GitHubの更新処理が完了したか |
| GitHub Pagesで404 | 公開元が `main` / `/(root)` か、その直下に小文字の `index.html` があるか |
| 苦手テストを押せない | その範囲に回答済み・正答率80%未満の問題があるか |
| 間違いのみが0問になる | 一度間違えても直近で正解すれば対象外。累計の苦手は別に残る |
| PCの記録がiPhoneに出ない | 端末間同期はないため正常。同じスマホ・ブラウザで継続する |

自動検証を実行する場合は、フォルダー内で `node --test tests/core.test.mjs` を実行します。現在のCSVの整合性チェックに加え、100〜200問へ増えたときの出題ロジックなども検証できます。問題追加後も、テストやアプリのコードを変更する必要はありません。


## 8. 類題で練習（追加機能）

スタート画面の「類題で練習」から開きます。元の100問と通常テストはそのままです。

- 英単語テスト①の50単語について、元の問題と異なる英文を各2問、計100問収録しました。
- 日本語訳・頭文字・文字数をヒントに、元のCSVと同じ英単語を入力します。
- 10・20・30・50・全問題から選びます。「全問題」は類題100問です。同じ単語の別例文が1回のテストに両方出る場合があります。
- ランダム出題、採点、Enter操作、もう一度、間違えた問題だけの再テスト、苦手問題に対応します。
- 類題の成績・最高点・前回選んだ範囲は、元のテストとは別に保存します。「学習状況」も類題のみの集計です。記録と苦手判定は例文ごとです。
- テスト②の類題はまだありません。①に②の単語を混ぜたり、未作成の類題を自動生成したりはしません。
- 「元のテストに戻る」で通常の画面へ戻れます。

### 類題CSVを追加・更新する場合

`similar.csv` の列は `index,SourceIndex,FrontText,BackText` です。

- `index`：類題ごとの重複しない番号（現在1〜100）。追加は101から続けます。
- `SourceIndex`：元の `words.csv` の単語番号。元CSVにindex列がない場合はデータの順番（見出しを除く）です。①は1〜50、②は51〜100です。
- `FrontText`：新しい英文・日本語訳・ヒント。空欄を設け、正答そのものは表示しません。
- `BackText`：元の該当単語と同じ正答。相違や参照先のない番号はエラーとして表示します。

UTF-8で保存し、GitHubの同名ファイルを更新します。例えば②の単語の類題を追加すると、類題画面にも「英単語テスト②」が自動で現れます。範囲は類題のindexではなくSourceIndexで分けます。元CSVを並べ替える場合は先に元の番号をindex列で固定してください。

追加ファイル：`similar.html`（類題画面）、`similar.csv`（問題）、`similar-core.js`（元単語との照合）。
共通の `app.js`・`core.js`・`styles.css` を使います。ローカル起動方法・GitHub Pagesの設定は同じです。
検証は `node --test tests/*.test.mjs` で実行できます。
